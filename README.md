# Existing Drive Sync — Obsidian для iPhone

Первая тестовая версия 0.1.3. Подключает локальное хранилище Obsidian к **уже существующей папке Google Drive**. Заметки остаются обычными файлами в вашей папке; другие устройства продолжают синхронизироваться привычным способом.

## Установка и обновления через GitHub / BRAT

Репозиторий: https://github.com/Ryukkw/obsidian-existing-drive-sync

1. В Obsidian откройте **Настройки → Сторонние плагины → Обзор** и установите **BRAT** (Obsidian42 - BRAT), затем включите его.
2. В настройках BRAT выберите **Add Beta plugin** и укажите `Ryukkw/obsidian-existing-drive-sync`.
3. Выберите последнюю версию и подтвердите установку. Если Existing Drive Sync уже установлен вручную, предварительно выключите его; папку хранилища, `data.json` и состояние синхронизации удалять не нужно.
4. Включите **Existing Drive Sync**. Подключение Google, выбранная папка и файлы заметок остаются в том же vault.
5. Для будущих обновлений используйте команду BRAT **Check for updates to all beta plugins and UPDATE**. В настройках BRAT можно включить проверку/обновление при запуске.

Релизы содержат отдельные `main.js` и `manifest.json`, необходимые BRAT. Штатная кнопка обновлений Obsidian начнёт работать после добавления плагина в официальный каталог; сейчас используется BRAT. Эта версия экспериментальная, проверка на реальном iPhone ещё не завершена.

Официальные инструкции BRAT: https://github.com/TfTHacker/obsidian42-brat/blob/main/BRAT-DEVELOPER-GUIDE.md

## Что сделано

- Выбор папки vault прямо в плагине с переходом по вложенным папкам, поиском в текущем разделе и разделом «Доступные мне».
- Двусторонняя синхронизация заметок, Canvas, PDF, изображений и других обычных файлов, включая вложенные папки. Искусственного ограничения числа файлов или общего объёма нет.
- Проверка при запуске, возврате в приложение, восстановлении сети, через 2,5 секунды после изменений и раз в минуту, пока приложение видно.
- При ручном запуске открывается окно прогресса, видимое и на iPhone. Оно показывает этап проверки, число найденных файлов на устройстве и в Drive, затем обработанные/всего файлов, процент, текущий файл и операцию. Счётчики отправок, загрузок, конфликтов и удалений обновляются по ходу работы.
- Прогресс также доступен в настройках плагина и через команду «Показать ход синхронизации». Длительные запуски показывают постоянное уведомление с кнопкой открытия прогресса. Закрытие окна не останавливает синхронизацию.
- Ошибка и частичный результат остаются видны до следующего запуска. Процент относится к обработанным файлам, а не к байтам; во время обнаружения файлов общее число ещё неизвестно, поэтому процент не выдумывается.
- Работа офлайн: файлы остаются на устройстве. При следующем успешном запуске синхронизации передаются изменения.
- Сравнение содержимого по MD5 и состоянию последней успешной синхронизации. Часы устройств не определяют победителя.
- Конфликты сохраняются в отдельном файле рядом с исходным: `Имя (conflict iPhone …).md`. Оригинальный путь получает облачную версию, отдельная копия содержит локальную. Обе версии отправляются в Drive.
- Удаления передаются только после предыдущего успешного согласования файла. Изменение с одной стороны имеет приоритет над удалением с другой.
- Заменяемые и удаляемые локальные файлы копируются в `.drive-sync-backups`. Облачное удаление использует корзину Google Drive.
- Состояние сохраняется после каждого завершённого действия. Полное перечисление файлов должно завершиться успешно до первых изменений: ошибка доступа не трактуется как пустая папка.
- Данные Google хранятся в Obsidian SecretStorage, а не в `data.json`. Промежуточного сервера нет.

## Установка на iPhone

Требуется Obsidian **1.11.4 или новее**, где есть SecretStorage. В каталоге `dist` находятся два архива:

- `existing-drive-sync.zip` — только плагин, для ручной установки в `<vault>/.obsidian/plugins/existing-drive-sync/`.
- `Drive-Notes-iPhone-visible.zip` (также `Drive-Notes-iPhone.zip`) — хранилище `Drive Notes` с уже вложенным плагином и видимой стартовой заметкой `START-HERE.md`. В архиве также есть отдельный `INSTALL.txt` с инструкцией. Удобнее для первой установки на iPhone: не нужно искать скрытую `.obsidian`.

1. Запустите Obsidian на iPhone и создайте локальное хранилище с любым другим именем, **без Save in iCloud**. Это создаст папку приложения в «Файлы → На моём iPhone → Obsidian».
2. Передайте `Drive-Notes-iPhone-visible.zip` через AirDrop. Распакуйте в «Файлах» (при появлении внешней папки архива откройте её: внутри находятся `INSTALL.txt` и `Drive Notes`) и перенесите **целиком папку `Drive Notes`** в «На моём iPhone → Obsidian». Не заменяйте папку существующих заметок.
3. Откройте `Drive Notes` в переключателе хранилищ Obsidian; если его не видно, перезапустите приложение.
4. Разрешите сторонние плагины и включите **Existing Drive Sync**, если он ещё не включён.
5. Добавьте подключение Google и выберите папку своего vault кнопкой «Выбрать папку», как описано ниже. Удалите стартовую заметку `START-HERE.md`, чтобы она не отправилась в ваши заметки Google Drive. Затем нажмите «Синхронизировать сейчас» и включите автоматическую синхронизацию.

Это путь установки для локальной сборки; он ещё требует проверки на реальном iPhone. Если приложение «Файлы» не перенесло скрытую конфигурацию, используйте файловый менеджер с доступом к скрытым папкам и скопируйте каталог плагина вручную. В стандартных «Файлах» iOS папка `.obsidian` не отображается. Официальная справка: https://obsidian.md/help/Files+and+folders/Configuration+folder

## Однократный вход в Google на Mac

Поскольку это ваш частный плагин без публичного OAuth-приложения, потребуется свой Google Cloud project. Один раз, не при каждом запуске.

1. Откройте https://console.cloud.google.com/ и создайте проект.
2. Включите **Google Drive API** в APIs & Services → Library.
3. Настройте **Google Auth Platform / OAuth consent screen**: имя приложения, свой email и аудиторию. Если выбран режим External / Testing, добавьте свой Google-аккаунт в Test users. В разделе Data Access добавьте scope `https://www.googleapis.com/auth/drive`.
4. Создайте OAuth Client ID типа **Desktop app**, скачайте JSON с параметрами клиента.
5. В терминале Mac выполните из каталога проекта:

   ```sh
   npm run auth -- /полный/путь/к/client_secret.json
   ```

6. В открывшемся браузере войдите в аккаунт, где лежат заметки, и предоставьте доступ. Помощник использует PKCE, случайный state и callback только на `127.0.0.1`; через 30 минут ожидание прекращается.
7. Получится `google-drive.credentials.json` с правами файла `0600`. Передайте его на iPhone через AirDrop, откройте текст и вставьте содержимое в поле **Подключение Google** в настройках плагина. Нажмите **Сохранить подключение**. Затем удалите переносную копию с телефона. В чат этот файл отправлять не нужно.
8. В настройках плагина нажмите **Выбрать папку**. Откроется список папок Google Drive: «Мой диск» или «Доступные мне». Перейдите в папку своего vault и нажмите **Синхронизировать этот vault**. Все заметки, вложения и вложенные папки будут синхронизироваться целиком. Копировать ссылку или выбирать отдельные файлы не нужно. Поиск в окне фильтрует папки текущего раздела.

OAuth scope `drive` технически предоставляет доступ ко всему вашему Drive, хотя плагин обходит только выбранную папку. Узкий `drive.file` не даёт автоматически прочитать все существующие файлы произвольного хранилища. Для полноценного выбора через Google Picker понадобился бы отдельный сценарий авторизации.

В External / Testing refresh token для Drive обычно истекает через 7 дней. Для длительной работы настройте подходящий режим публикации OAuth-приложения в Google Cloud; требования к подтверждению зависят от аудитории и типа аккаунта. Пока приложение остаётся в Testing, после истечения доступа потребуется повторить `npm run auth` с новым именем выходного файла и импортировать подключение заново. Документация: https://developers.google.com/identity/protocols/oauth2#expiration

## Как включать в существующую схему

Плагин предназначен прежде всего для **локального хранилища на iPhone**. На компьютерах с работающим Google Drive for Desktop не включайте его дополнительно для той же папки: там уже действует ваш текущий механизм синхронизации.

Первая синхронизация объединяет существующие файлы. Отсутствующий на телефоне файл скачивается, отсутствующий в Drive локальный файл загружается. Два разных файла по одному пути сохраняются как конфликт. Для первого подключения сделайте копию исходной папки: скачивание через реальный Google Drive API проверено, но полный цикл синхронизации на реальном iPhone ещё не проверен.

## Что не синхронизируется

- Папка конфигурации Obsidian (`.obsidian` или пользовательская `vault.configDir`), `.git`, `.trash`.
- `.drive-sync-state` и `.drive-sync-backups` — служебное состояние и локальные резервные копии.
- Пустые папки: родительские папки создаются при передаче файлов. Переименование обрабатывается как перенос содержимого через создание и удаление; пустые старые папки могут остаться.

Google Docs/Sheets и ярлыки Google Drive не являются обычными файлами заметок. Если они есть в выбранной папке, синхронизация останавливается с указанием пути. Дубликаты имён, несовместимые с iOS имена и коллизии регистра тоже останавливают синхронизацию, вместо выбора случайного файла.

## Практические ограничения первой версии

- В выгруженном iOS приложении плагин не работает. После правок дождитесь завершения синхронизации перед закрытием; иначе изменения отправятся при следующем открытии.
- Каждый проход полностью перечисляет дерево Drive и хеширует локальные файлы. Передаётся только изменённое содержимое. Ограничения числа файлов нет, но крупное хранилище будет проверяться дольше.
- Один файл читается в память целиком; отправляется блоками по 1 MiB. Максимальный практически возможный размер отдельного вложения зависит от памяти iPhone. Сохранение позиции незавершённой загрузки между запусками пока не реализовано: передача повторится.
- В Drive используется API v2: он явно возвращает `etag`. При скачивании метка `etag` из metadata не отправляется в `alt=media`: у содержимого другая метка версии, что подтверждено read-only проверкой настоящего Google Drive. Скачанные байты проверяются по MD5 из полного списка файлов. Перед заменой и удалением сверяются metadata, а в запросах передаётся `If-Match`. Это не общая блокировка всех устройств. Реальное поведение условных запросов, особенно при завершении resumable upload одновременно с чужой правкой, нужно подтвердить интеграционным тестом.
- Между проверкой локального содержимого и записью остаётся короткое окно гонки: файловый адаптер Obsidian не предоставляет атомарную операцию compare-and-swap для произвольных бинарных файлов. Резервные копии уменьшают риск потери исходной версии, но не заменяют проверку на устройстве.
- Резервные копии автоматически не удаляются. Управляйте `.drive-sync-backups` по мере необходимости.
- Файл состояния привязан к устройству и исходной папке Drive. Для другой папки создайте другое локальное хранилище.
- SecretStorage — стандартное хранилище секретов Obsidian; плагин не заявляет, что это отдельное шифрование ваших заметок или независимый защищённый аппаратный контейнер.

## Проверки и сборка

```sh
npm ci
npm test
npm run package
```

Автоматические проверки покрывают трёхстороннее согласование, конфликты, удаление, ошибки сети, сохранение прогресса, гонки правок, бинарные файлы, небезопасные пути, дубликаты имён, пагинацию Drive, условные запросы и протокол загрузки. Сетевой транспорт в автоматических тестах подменён. Дополнительно исправление 0.1.2 проверено read-only скачиванием одного файла через настоящий Google Drive API с проверкой MD5. Полный цикл записи/удаления и работа на реальном iPhone ещё требуют проверки.

Следующий этап проверки на устройстве: вход Google, загрузка настоящей копии папки, правка в обе стороны, режим полёта, возврат из фона, конфликт одновременных правок, пустой файл, вложение больше 1 MiB и удаление с восстановлением из резервной копии/корзины.

## Обновление 0.1.2: ошибка «Файл в Google Drive изменился…» при скачивании

Исправлено ложное срабатывание HTTP 412 при скачивании: metadata ETag нельзя использовать как If-Match для media-ответа. Реальный read-only запрос к Drive подтвердил: с metadata If-Match — HTTP 412, без него — успешное получение байтов. Проверка MD5 остаётся обязательной, условные запросы записи и удаления не изменены.

Для обновления установленного плагина используйте `dist/existing-drive-sync-0.1.2.zip`. Обновляйте именно плагин, сохраняя хранилище заметок и подключение Google. При установке через Pluscan: скопируйте ZIP в видимую папку `_plugins` своего vault, запустите `Pluscan: Scan now`, выберите Existing Drive Sync 0.1.2 и подтвердите обновление. После установки выключите и включите Existing Drive Sync. Pluscan доступен в каталоге сторонних плагинов Obsidian, поддерживает мобильные устройства и требует Obsidian 1.13.0+. Отдельное iOS-приложение не требуется.
